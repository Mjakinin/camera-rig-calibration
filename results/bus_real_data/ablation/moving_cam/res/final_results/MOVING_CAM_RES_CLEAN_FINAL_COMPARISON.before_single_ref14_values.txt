==========================================================

Scope:
Camera-to-GT comparison for moving-camera resolution ablation.
Translation error in cm. Rotation error in degrees.

Final source policy:
- AP01: relative cam3-local camera-map, evaluation-only SE(3) alignment to GT camera map, no scale.
- AP02: official GT-aligned full-map SE(3) evaluator, no scale, static cameras + markers 0..13, marker14 held out.
- AP03-SINGLE-REF14: targetless COLMAP reconstruction followed by single Ref14 metric registration; GT is evaluation-only.
- AP03-MULTI-ARUCO: targetless COLMAP reconstruction followed by Multi-ArUco metric registration; GT is evaluation-only.
- AP03 source gating: use method-final files only; copied hashes, incomplete camera sets, and repo_like/debug intermediates are rejected.
- MISSING_SOURCE means the method variant is conceptually valid but no accepted variant-specific final source exists yet.
- EXCLUDED means the method/variant was rejected due to a concrete validity problem.

Compact interpretation:
- AP03 is now split into AP03-SINGLE-REF14 and AP03-MULTI-ARUCO.
- AP03-MULTI-ARUCO is best where valid: 640x360 = 2.822 cm / 0.405 deg, 960x540 = 3.213 cm / 0.140 deg, 1280x720 = 1.287 cm / 0.162 deg.
- AP03-MULTI-ARUCO is explicitly excluded at 320x180 and 1920x1080 because the selected COLMAP model is incomplete for the four-camera rig.
- AP03-SINGLE-REF14 is currently source-backed only for 1280x720_baseline; other RES variants require source recovery or rerun before numeric inclusion.
- Both AP03 variants keep COLMAP targetless; ArUco is used only after reconstruction for metric registration.
- GT camera poses are not used for AP03 fitting; GT is used only for final error evaluation.
- AP01 is available for all resolutions and remains a relative camera-map evaluation, not absolute world-pose estimation.
- AP02 is available for all resolutions but is more resolution-sensitive, with the best mean translation error at 960x540.

Reusable finalization workflow:
1. Run each AP method per ablation variant and freeze the method outputs.
2. Build a source-gated row set: only method-final, variant-specific files are accepted; copied hashes and intermediate files are rejected.
3. Split AP03 into AP03-SINGLE-REF14 and AP03-MULTI-ARUCO for all future ablations.
4. For rejected method/variant combinations, keep a row with status EXCLUDED or MISSING_SOURCE and a precise reason.
5. Write exactly one final TXT into the ablation final_results folder.
